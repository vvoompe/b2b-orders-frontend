## 1. Які інструменти використано

| Інструмент | Модель | Межі використання |
|---|---|---|
| Hermes Agent (асистент у терміналі/чаті) | [вказати модель, яку фактично використано] | генерація ідей, структура, чернетки тексту й коду, пояснення помилок |
| Вебпошук усередині асистента | - | пошук офіційної документації; усі зовнішні джерела зведено в §4 |

Інші інструменти генеративного ШІ не використовувались. Дані з обмеженим доступом, персональні
дані третіх осіб і службова інформація до ШІ не передавались.

## 2. Що саме виконував ШІ (дозволені категорії)

1. **Генерування ідей** - перелік можливих тем, екранів, станів інтерфейсу.
2. **Структура тексту** - каркас пояснювальної записки та керівництва користувача.
3. **Варіанти формулювань** - чернетки абзаців, які автор далі правив під свій виклад.
4. **Пояснення** - розбір понять (діаграма станів, mock-API, адаптивність) і пояснення
   повідомлень про помилки збірки/тестів.
5. **Чернетки програмного коду** - початкові версії компонентів і тестів; остаточна логіка,
   правки та перевірка - автором.

## 3. Що саме виконав автор особисто (обов'язкова частина)

- вибір теми, предметної області та функціональних вимог, узгодження формулювання з лектором;
- побудова діаграм (користувача та станів) і написання їх вербального опису;
- запуск застосунку на власній машині, перевірка кожного екрана в браузері, ручні прогони
  сценаріїв (вхід → список → картка → перерахунок прогнозу);
- реальні прогони `npm ci`, `npm run build`, `npm run lint`, `npm test` і фіксація їх виводу;
- зміни в згенерованому коді: [перелічити власні правки - текстом, конкретно];
- написання двох мікрозмін «на льоту» для захисту: [описати обидві];
- фінальне вичитування тексту записки та відповідальність за кожне твердження.

## 4. Використані джерела інформації (вебдоступ)

Усі джерела, до яких звертався асистент із вебдоступом, зведено в бібліографічний список
пояснювальної записки (див. розділ «Список використаних джерел», оформлений за
ДСТУ 8302:2015). Окремо зазначаю: жодне з джерел не відтворено в роботі дослівно, всі
запозичені технічні факти перевірені на практиці запуском коду.

## 5. Межі використання ШІ (чого не робилося)

- до роботи не включено жодного згенерованого фрагмента без критичної перевірки та адаптації;
- не використовувались інструменти, що формують узагальнений текст на основі вебджерел, без
  самостійної інтерпретації (вебпошук застосовувався лише для офіційної документації);
- ШІ не використовувався для відповідей на захисті та не подавався як автор роботи;
- код і текст перевірені запуском; усі наведені в записці результати (збірка, тести, покриття)
  отримані реальними прогонами, а не згенеровані.

## 6. Чек-ліст автора перед поданням (заповнюється руками)

- [ ] прочитано кожен файл коду й зрозуміло, що він робить (перевірка «що, чому, що зламається, якщо прибрати»);
- [ ] застосунок запущено локально, усі 5 екранів відкрито в браузері;
- [ ] перемкнуто й перевірено всі стани (loading / empty / error / offline; 6 станів кнопки);
- [ ] виконано `npm run build`, `npm run lint`, `npm test` - вивід збережено;
- [ ] внесено власні правки в код (мінімум 3 змістовні) і по 1 мікрозміні на 2 екрани для захисту;
- [ ] перевірено README: інструкція «запуск з нуля» працює на чистому клоні;
- [ ] текст записки вичитано, формулювання відредаговано під власний виклад;
- [ ] декларацію (цей файл) оновлено фактичними даними та підписано.

*Незаповнені пункти = декларація неповна; за політикою дисципліни недеклароване використання
ШІ тягне множник доброчесності M = 0,5, а подання чужої роботи як своєї - M = 0,0.*
